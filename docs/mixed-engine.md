# 中日混合解码（2026-09-26）

本次新增离线句内联合分词/语言选择/整句组合，替换原来的两套整串候选拼接。
`jintianyearigatou` 和有受限纠错的 `jintianyearigadou` 都可得到
`今天也ありがとう`；选择 `今天也` 后仍保留 `arigatou` 继续解码。反向、
中→日→中、多次部分选词、删除解锁和再次编辑也走同一状态机。

## 代码与 UI 并行修改的边界

- `SKConversionEngine` 只做模式路由：中文/双拼仍是 `SKRimeEngine`，日文仍是
  `SKJapaneseEngine`，中日混独立使用 `SKMixedEngine`。切换先成功构造新引擎，
  构造失败时旧引擎仍可用。原有 Rime 用户词典与纯模式处理未替换。
- `SKMixedEngine` 管原始输入、已选范围、剩余串、候选 ID、分页、提交与本地学习。
  输出文字长度不参与计算消耗的字母数。已选前缀只进入 preedit，不提前重复上屏。
- `SKMixedDecoder` 管中文/日文词图、有界搜索、词性连接、跨语言评分和纠错。
  无 UIKit、系统文本框访问或网络依赖。
- `SKMixedChineseLexicon` 是同一份万象数据的只读映射索引，提供词频与边界；
  `SKJapaneseLexicon` 继续提供 Mozc 词/POS/连接数据。不会每个子串创建 Rime 会话。
- `Core` 只有两项必要兼容扩展：混输组合中的日文长音键，以及候选的可选
  `consumedInputCount`。原 `SKCandidate(index:text:comment:)` 构造仍有效。
  `SKInputSession` 以“文字+消耗范围”去重，保证同文异范围候选不被吞掉。

**没有修改 `ShikaKeyBoard/UI/`、`KeyboardViewController.swift`、键盘布局、
主应用页面或 Xcode 项目文件。** UI 继续显示 `SKEngineState`，并把收到的
`SKCandidate` 原值回传给 `onSelect`；不要从按钮文案重新拼装候选。UI 无需知道
语言标签、路径评分或词库类型，后续界面修改可独立进行。

## 搜索、排序和状态约束

同时保留不同词边界及语言路径，不先把整串硬分类成中文或日文。
中文词频和日文词/POS 成本经开发集校准后进入同一搜索；语言切换是有限代价，
不是硬锁。已选择的前文参与日文 POS 连接及本地跨语言相邻词偏好。

每个位置保留16条路径；解码最多96个原始字符，每个词最多40字符。达到边界时
原始输入仍完整保留，长尾可以分段选择或原码确认，不截断用户输入。
查询缓存有明确容量；每键先查询一次当前中文候选，再对最有希望的中文片段
最多补4个不同查询，以 Rime 句子候选精排；缓存复用跨按键的相同片段。
中文纠错沿用现有只读纠错词库。日文混输纠错限定为活跃尾段的单次清浊音替换
或相邻转置，必须命中完整词，且增加成本。**这不是完整日文自动纠错系统。**

显式拼音分隔符禁止词索引跨越（`xi'an` 不作为 `xian` 单音节），Rime 可以
提供跨显式音节边界的整句；日文 `n'` 保持其读音规则。

空格选择当前首候选；Return 确认“已选文字+剩余原始字母”，不执行发送/换行。
标点与模式切换一次性 flush，若候选只消耗前缀，尾串仍原样保留。
删除先退原始尾串，再逐段恢复已选词的原始拼写。展开候选不改输入或学习。
学习仅在完成选择时记录词和相邻词对，容量最多2048项，有界提升且持久化；
清空/宿主切换清除当前上下文，打字、浏览、取消不写学习文件。

## 日文与现代词源

现有 Mozc OSS 十分卷不是 Google 私有 Web 词库。本次补全同一固定快照的
官方 manual words/places 和 aux，并运行上游生成器继承 POS、成本中位数及
aux 成本偏移；没有以测试答案单独补词。官方部分去重后新增226词/POS记录。

另在测试结果揭晓前，按两篇发布方2025/2026趋势报告整理10个事实性词头/读音，
包括メロい、エッホエッホ、ぬい活等。没有复制文章正文、调查回答或整句进词库。
官方+现代补充去重、展开后共新增235记录；最终日文索引1,281,733记录，
744,383读音。13个补充词专项全部在Top10（ChatGPT使用正确的`thi`表示てぃ）。
来源、固定hash、完整许可与变换见 `Vendor/Lexicons/README.md`、
`japanese-modern-sources.json` 和 `docs/mixed-corpus-research.md`。

新增中文联合索引94.5MiB磁盘空间，映射读取，不等于常驻内存。纯中文仍保留
完整Rime词库；联合索引单读音最多12同音词、最多64字母，运行词搜索上限40。
这些是明确的裁剪范围，不宣称词库完备或任意长句都能一次命中。

## 250项质量评测与证据

独立作者冻结250项，按日文核心词族划分52开发/198保留，未按输出修改目标。
其中188条正常混输、60条单语言输入对照、2条开发探针。8条网络短摘经去标点/
简化字形/转写改编，其他是有词源记录的设计表达，**不是250条真实聊天采样**。
5处可证实转写笔误静态修订为fixture v2，旧/新hash与原因均有记录。

开发集比较16/32/64条路径时命中数量相同，P95约15.7/24.3/46.9ms，因此选16。
旧新引擎使用同一更新后的词库、独立新进程/用户目录，不选词训练后再跑排名。
候选必须覆盖全部输入才能算新引擎整句命中；部分候选占据的可见排名仍计入。

| 固定集合 | 首选 | 前3 | 前5 | 前10 |
|---|---:|---:|---:|---:|
| 全部250项，新混输 | 80.8% | 88.4% | 92.0% | 94.0% |
| 未调参混输144项，新混输 | 77.8% | 84.7% | 88.9% | 91.7% |
| 同144项，旧整串候选拼接 | 0% | 0% | 0% | 0% |
| 未调参单语言输入54项，仍在混输模式 | 90.7% | 98.1% | 100% | 100% |

旧版0%指这组跨语言**完整句子**，不意味着它不能输出单个日文词。
完整逐项结果、失败和预登记阈值在 `docs/evidence/mixed-engine/`；保留集达到
事先设定的Top5≥70%、Top10≥80%、单语言Top5≥95%的验收线。

- 独立行为/跨进程学习：54/54；本次质量runner另有27项行为检查通过。
- 原中文/双拼输入会话：55项及用户词学习/共享运行时检查通过。
- 日文既有40词：Top5 100%，功能/提交/学习79项通过。
- iOS实际控制器/UITextView：250项、6137键无提前提交，另7个上屏流程断言，
  合计6144次检查通过。截图验证整句候选、选中文后日文余串、多次切换和提交。
- iOS回车专项：50项通过；iphoneos应用/扩展编译和离线资源检查通过。

iOS模拟器优化构建：引擎按键P50 **4.9ms**、P95 **15.4ms**、P99 **22.0ms**。
语料遍历的最大采样physical footprint **34.7MiB**；含UI/截图后 **55.4MiB**。
这些是测试宿主的采样，不是精确连续峰值，也不是手机键盘扩展的内存保证。
按键延迟针对引擎调用，不包含完整触控/绘制链路。没有把编译成功当作运行验收。

仍失败的主要是中文同音歧义与短日文/拼音重叠，如パン/盘、ガチャ/嘎查，
以及“汤真/塘镇”“借过/结果”。这版使用词频、POS和个人选词上下文，未训练
大型中日语义模型，不能保证仅凭无上下文短音就猜中意图。失败样例完整保留，
没有针对保留集追加词条或调权。后续可用真实授权混语语料改进上下文模型。
