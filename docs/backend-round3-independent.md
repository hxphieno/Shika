# 第三轮引擎优化：独立验收

本报告由没有修改本轮生产实现的独立 agent 编写。验收范围为静态纠错搜索、已学词编辑距离、候选组合与查询复用；不把合成测试通过率当作自然语料准确率，也不把减少调用次数直接当作真机延迟收益。

## 候选与选择路由

`Tests/BackendRound3CandidateChecks.swift` 创建两条记录的小型纠错索引，使用固定原生查询响应和计数 spy。旧实现为 **17/17**，局部缓存实现为 **18/18**；新增的一项检查要求一次展示内每个代码只查询一次。

- 同一 `shijie` 修复代码对应静态候选和四个已学同音词：查询 **5 次 → 1 次**。
- 新旧候选文本、顺序、注释及每项选择路由完全一致。
- 下一次 `present` 的模拟原生首选从“世界”变为“视界”，新排序立即可见，没有跨事件复用旧结果。
- 保留所有前导精确同音候选；近似拼写排在这些精确候选之后。
- 同文本的原生部分候选被完整纠错路由替换；其他部分候选保留。
- 已学词必须通过原生文本与完整拼写核验；错误读音和不存在的词不进入列表。
- 空输入、翻页、已提交文本和包含汉字的部分选词态不发起纠错查询，并清理上一次选择路由。

这是路由层单元验收，不是对真实 Rime 出词质量的替代。真实引擎的候选对照、学习和构建验收由主任务补充。

## 已学词独立编辑距离 oracle

`Tests/BackendRound3LearnedOracleChecks.swift` 不复用生产扫描实现。它逐条枚举目标词，独立删除或交换字符，计算允许的一次编辑和相邻交换，然后按既有成本与最近记录顺序选前四项。

- 双拼、全拼各 **328 条合法记录**、**3,282 个输入**。
- 穷举字母 `a/b/c` 的 3 至 7 字符输入，补充大小写、标点、非 ASCII、空输入及 47/48/49/50 字节边界。
- 覆盖重复字符、首尾交换、相邻但不是交换的两个差异、三处差异、相同代码的多个词及其最近记录排序。
- 旧实现与“长度提前过滤 + 扫描提前返回”实现均为 **6,564/6,564**，完整结果报告相同。

## 静态纠错搜索 oracle

`Tests/BackendRound3SearchOracleChecks.swift` 用合成、排序后的二进制词典，独立对所有词条计算最小允许编辑成本和排序，不调用生产的变体生成或二分比较逻辑。

- 冷查询、立即重输、超过缓存容量后的再次查询，总共 **25,596/25,596**。
- 覆盖有效双拼音节对、插入/删除/替换/交换、重复字符、键位距离成本、得分相同的代码排序、前 12 项上限、非法输入和长度边界。
- 这是未改动的静态搜索基线验收；本轮尝试的键位距离表和 `memcmp` 方案没有因通过等价性检查就自动被采纳，仍由性能证据决定。

## 审查结论与限制

局部查询复用没有扩大缓存生命周期，已学词扫描没有修改编辑阈值、成本或排序。独立验收没有发现需要修改候选排序策略的明确准确性缺陷，因此本报告不宣称准确率提升。

测试输入是刻意构造的算法与路由边界；实际 Rime 的学习、内存、候选质量和设备延迟仍需真实引擎验收。性能试验期间本 agent 停止了编译及密集计算，避免与主任务计时互相干扰。
