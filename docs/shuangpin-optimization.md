# 输入法体验优化：双拼优先

> 本文记录原小鹤方案的优化实验。当前已切换为[自然码双拼](ziranma-shuangpin.md)，历史报告中的按键编码与指标保留原样。

本轮只修改引擎、离线方案配置与测试，不修改键盘 UI、布局、按键语义、输入会话策略或主应用。双拼优先，其他模式可以独立接受有益改动。开始时主应用 `Shika/ContentView.swift` 已有外部修改，不属于本轮提交。

## 实验顺序与准入

1. **等价搜索优化**：利用实际双拼音节映射排除不可能命中词典的编码；缓存只读拼写建议，不缓存用户词排序。要求候选序列及提交结果与基线一致，并测量冷输入及删除重输。
2. **原生 Rime 音节纠错**：比较默认关闭、主会话开启与隔离的辅助会话。原生音节图可以检索词库外组合和已学用户词；不依赖固定整词纠错索引。只有不退化正确输入、实际可提交且成本可接受的方案才保留。主会话变更若有副作用则放弃，不能用总命中率掩盖退化。
3. **其他模式的独立收益**：仅推广通过本模式验收的变更。外部语言模型、跨输入框上下文及触点模型涉及资源/许可或 UI 交互边界，本轮先评估可行性；没有可靠证据的不默认启用。

## 参考实现

- Rime 1.17.0 的 [Corrector](https://github.com/rime/librime/blob/1.17.0/src/rime/dict/corrector.cc)、[ScriptTranslator](https://github.com/rime/librime/blob/1.17.0/src/rime/gear/script_translator.cc) 和 [Memory](https://github.com/rime/librime/blob/1.17.0/src/rime/gear/memory.cc)：优先复用已集成的 BSD 核心，实现音节级容错、原生选词和用户字典学习。该版本实际启用的是邻键搜索，不能宣称通用编辑距离纠错。
- [万象语言模型](https://github.com/amzxyz/RIME-LMDG/releases/tag/LTS)：提供整句搭配；需要模型大小、真机成本及数据许可评估，不能将桌面效果等同于键盘扩展收益。
- [Octagram](https://github.com/lotem/librime-octagram)：插件采用 GPL-3.0，不能当成现有 BSD 核心直接加入发布包。
- [Gboard 2024 论文](https://aclanthology.org/2024.emnlp-industry.93/)：联合搜索和上下文评分的参考，不是可直接移植的 iOS 中文权重。

## 验收约束

- 冻结旧版源码与资源，基线为旧版**已开启纠错**，而非无纠错版本。
- 独立准备新语料、按目标词分开发/保留集；排名进程不选词，提交/学习使用独立用户目录。
- 正确输入首选不因新纠错而改变；打码意外上屏、错误删除、上屏残留、重复提交为硬失败。
- Top1/3/8 分错误类型报告；可见候选不等于完整可提交，部分候选不得当作完整修复成功。
- 相关旧回归、独立行为验收、模拟器生产控制器及构建验证；不以全量测试次数替代针对性检验。
- 延迟/内存注明进程与平台。冷输入和重复输入分开，不拿热缓存结果冒充冷性能；暂不声称实测真机扩展。
- 每个保留改动独立 commit；被放弃方案只保留实验记录。

## 已保留：只读拼写搜索优化

400 条旧纠错回归的候选序列逐项相同；拼写建议的编码、文本、成本和频率签名相同。独立查询基准每词新建索引对象，区分首次输入与立即删除重输，重复三轮：双拼冷查询 P95 2.827→0.843ms，P99 13.304→2.493ms；重复查询 P95 0.658→约0.001ms。全拼只推广64项只读结果缓存，用户词的 Rime 排名每次仍重新查询。缓存容量上限64项，不持久化用户输入。

这些是 macOS **拼写索引函数**耗时，不是完整引擎或触屏响应；首轮整引擎实验与其他编译重叠，波动明显，未用于宣称提速。证据见 `evidence/shuangpin-optimization/search/`。正确输入、提交、学习的完整回归在最终阶段继续检查。

## 已保留：双拼候选恢复与已学词纠错

对应提交 `6c1db09`，全部在 Engine 和离线方案生成层：

- 原来的三个优先纠错编码保持次序，从已查询到的真实 Rime 结果中再保留最多两个同音词，避免只取每码第一词而遗漏其他正确词。
- 增加一个隔离的、只查询的 Rime 音节辅助会话，复用已有 prism、词典和用户字典。主会话方案不打开新的纠错开关。辅助结果最多三个，保留已有前三项和完整候选的优先位置，已有部分选词继续由原生组合处理。
- 为实际完整上屏的中文双拼词保存有界 code/text 元数据，最多512条、最多4个建议、读取文件上限128 KiB；不另算词频，不记录错码，不记录浏览、取消和 Return 原码。建议再次经过 Rime 用户词查询确认，最终选词仍交给主会话完成提交和学习。
- 元数据在后续使用中积累，不会自动导入升级前所有历史用户词；支持一次替换、漏键、多键、相邻交换，不承诺任意多错恢复。持久化写失败时回退为当前内存结果，已有原生用户字典仍独立工作。

只读音节缓存最多32项，选词、提交和切换方案时失效。静态拼写缓存最多64项；新增用户词不依赖该缓存。没有引入下载、大语言模型、新增联网权限或第三方原生库。辅助 schema 可由 `scripts/generate-rime-assist-schemas.py` 重建，`--check` 检查派生资源是否同步。

所有基线均为本轮开始时**已经启用旧纠错功能**的生产引擎。排名不学习答案；只有完整消费输入的候选才算命中。下表单错包含替换、漏键、多键和交换四类，不把双错混入分母。

首次未达门槛没有被删除或改阈值。期间试验更大编码预算和同码轮流插入，在开发集上反而较差，已撤回；之后固定最终参数，在独立追加的480条确认集首次运行后不再根据其结果调参。确认集80个目标与此前全部测试目标无重合。新用户词索引解决独立行为验收暴露的问题；确认排名采用空用户数据，不以事先学习来提高分数。

双拼确认集的80条正确输入：Top1仍62，Top5仍75，首选文字逐项不变。320条单错的Top1仍85，没有提高；主要收益是更多正确候选可以找到和选择。80条双错Top5从0到10。长句仍是明显短板：48条长句单错Top5仅0→3，不能宣称已达到成熟整句纠错水平。各类型、词长、分区、类别和未命中ID保存在 `quality/*summary.json`。

本轮新双拼语料1320条，是220个目标的设计与词源改编测试；全拼840条与其中140个目标共享词汇，重新构造全拼错键，**不是另一份独立词汇语料或自然用户日志**。全拼初版文件错误继承了双拼 edits 元数据，之后只修正可复现的全拼编辑描述，840条实际排名输入、目标、ID和分区逐项保持不变；原冻结记录和勘误都保留。

## 验收与资源成本

- 独立 agent 对真实 Rime 和生产输入会话执行117项双拼行为、学习、跨进程恢复与索引边界检查，全部通过；保留首次开发失败及修复前后记录。中文独立对比旧版60项、新版66项全部通过，24组输入的首选及原生完整候选顺序相同。
- 逐例新进程、新用户目录的完整上屏回放：双拼确认集305/305、首轮保留集494/494、开发集92/92、全拼扩展集571/571、旧回归373/373，共1835次全部通过。要求一次提交等于目标，input、preedit、候选清空，再次commit不重放；不是仅看候选列表文字。
- 旧纠错交互32项在本轮基线与新版均通过。修正一条过期测试：以前误要求Return选首词并换行，现按已确认的原始字母提交语义检查；生产按键逻辑不改，原失败日志保留。
- 中日混的独立交互、学习、跨进程回归通过；真实UITextView模拟器Return专项50项通过。iPhone目标无签名构建成功，离线资源、静态Rime、隐私文件、声明文件和关闭完全访问的打包检查通过。这不是实机安装或App Store审核结论。
- 最终双拼确认排名的macOS逐键P95为1.008→1.173ms，P99为2.457→3.007ms，符合预设延迟门槛；启动48.71→75.30ms，峰值RSS76.52→98.20MiB，存在约21.69MiB成本。旧400回归首次与编译并发发生延迟异常，双方同样重跑后P95为1.745→1.555ms；所有轮次保留，不拿异常慢基线宣称提速。
- iOS26.5模拟器UIKit宿主的300次切换、1687按键、生产键盘候选点击上屏和截图验收通过。最终P95为1.531ms，切换结束phys_footprint约35.02MiB，UI绘制释放后约49.08MiB；120→300次切换的增长/波动均48KiB。稳定性阈值保持后期增长8MiB/波动12MiB，未因本次结果改阈值。详细采样和构建参数见 `simulator/` 与最终 `simulator-release/`。模拟器压力测试复用测试App的沙盒，不当作全新用户准确率测试。

上述macOS RSS与模拟器phys_footprint口径不同，不能互相抵消或推算真机键盘上限。最终真机扩展内存、自然输入分布以及长句首选仍需后续单独评估，本轮没有手机实测结果。截图使用生产键盘控制器和测试文本代理，Return专项另用真实UITextView，均明确不是系统扩展进程。

全拼840项单轮P95为4.862→6.046ms，约1.244倍，低于预设门槛；但新版执行期间与另一组隔离提交进程短暂并发，不能称为严格隔离负载的测量。相关原始耗时保留，不据此宣称全拼整体提速。

较大的逐候选原始报告以 `.json.gz` 无损归档，汇总、失败记录和提交摘要仍为普通文本。`compressed-reports.json` 保存解压后原始SHA-256；汇总与提交回放脚本均直接支持压缩输入，没有丢弃失败样本或候选。

## 放弃的方案

音节纠错直接插到第一项之后会降低开发集Top3，未保留；辅助查询page从8增至16无质量收益，未保留；同码候选轮流分配及静态编码预算从3增至4，均不及当前开发结果，未保留。实验原始输出在 `experiments/`。大模型、Octagram、触点模型及跨输入框上下文未接入，不能视为本轮已经具备的能力。

## 复现入口

`scripts/test-shuangpin-optimization.sh <临时目录>` 冻结并编译当前引擎，runner接收 `resources fresh-user cases.json report.json development|heldout|all`；不要复用排名用户目录，不要在排名前选词学习。`scripts/summarize-shuangpin-optimization.py before.json after.json summary.json [cases.json]` 汇总排名、分组及门槛；`scripts/check-shuangpin-commits.py runner resources cases.json ranking.json output-dir` 对完整命中逐项用新进程提交。`bash scripts/test-shuangpin-behavior.sh <输出目录>` 重跑117项独立行为和索引验收。语料生成和独立验收协议见 `evidence/shuangpin-optimization/PROTOCOL.md`，独立复核结论见 [独立验收报告](shuangpin-optimization-independent-validation.md)。
