# 第三轮引擎优化：减少重复查询与已学词搜索成本

2026-09-26。基线 `a53f2b3`。本轮只修改 `SKCorrectionCandidates` 和 `SKLearnedSpellingIndex`，适用于现有双拼及中文全拼纠错路径。UI、按键语义、原生词频、纠错距离、候选数量、词库和日文/混输算法没有调整。

功能提交：`b41e39f`（已学词搜索优化）、`46dbb75`（同次候选查询复用）。报告和原始证据独立归档。

## 社区参考与选择

- [SymSpell Lookup](https://github.com/wolfgarbe/SymSpell/blob/master/SymSpell/SymSpell.cs)在距离计算前检查长度差，并避免重复处理已经考虑过的建议。本轮借鉴这两种减少无效工作的原则，没有引入它的删除索引、依赖或排名规则。
- [Mozc DictionaryPredictor](https://github.com/google/mozc/blob/master/src/prediction/dictionary_predictor.cc)在处理纠错时分别考虑相同读音和相同文本，并区分精确匹配、预测与部分消耗。本轮据此重点检查完整纠错与原生部分候选的路由，以及精确同音词保护；没有发现足够证据支持改动现有排序，不宣称准确率提升。

## 保留：同次候选展示内复用原生查询

静态纠错和多个已学同音词可能要求查询同一个编码。现在每次 `present` 仅查询一次该编码，保存经过完整拼写核验的候选；本次展示结束即释放。下一次输入、选词或展示仍查询最新 Rime 状态，不跨事件缓存学习排名。

独立计数 spy 中，`shijie` 的静态修复与四个已学同音词合计原先查询5次，现在1次，候选文本、顺序、注释及选择路由完全相同。原版17/17、新版18/18（新增一次查询约束）；下一次展示切换原生首选也立即生效。这是确定的调用次数收益，不是实测手机耗时降低80%。

缓存仅保存本次有界查询的结果，不增加磁盘数据，不修改Rime主会话。普通无同码复用场景仍有一个小型字典的管理开销，后文真实引擎对照未观察到明显整体退化。

## 保留：已学词匹配提前排除不可能结果

1. 先比较输入与条目UTF-8长度，长度差大于1时直接跳过，避免创建条目字节数组。
2. 等长编码首次发现差异后，第二处差异必须是紧邻、互换的字符；否则立即返回。替换、插入、删除成本1，相邻交换成本0.85，精确输入不重复推荐的规则保持。
3. 最近记录优先、最多四条建议、512条/128KiB持久化限制都不变。

性能输入在测量前冻结：用固定种子20260927从随包双拼/全拼纠错词典分别抽样512条合法记录，分别产生精确码、替换、遗漏、插入、相邻交换和前缀。双拼3284个不同输入，全拼3270个；分别测0、64、512条记录，每组重复5轮。结果和原始数据在 `evidence/backend-round3/learning/`。这是受控搜索负载，不是自然文本输入准确率。

初次测量与其他编译重叠、噪声明显，保留为 `excluded-contended-*`，不用于结论。独立agent停止密集计算后，按“组合新版→旧版→仅长度过滤→旧版→组合新版”串行复测，19,662条有序结果签名全部相同。

| 已学记录数 / 模式 | 旧版P95（两轮） | 新版P95（两轮） | 查询累计耗时下降 |
| --- | --- | --- | --- |
| 64 / 双拼 | 0.00733 / 0.00729ms | 0.00313 / 0.00288ms | 65%–68% |
| 512 / 双拼 | 0.06213 / 0.06333ms | 0.02463 / 0.02454ms | 69%–70% |
| 64 / 全拼 | 0.00567 / 0.00558ms | 0.00175 / 0.00171ms | 约76% |
| 512 / 全拼 | 0.04250 / 0.04196ms | 0.01400 / 0.01388ms | 约75% |

仅长度过滤也有收益，但512条时双拼P95为0.04858ms、全拼为0.02742ms，慢于组合方案，因此保留组合实现。空记录的查询仍在计时分辨率附近，不能声称有可感知差异。

这些是macOS的已学词索引函数数据，绝对节省约几到几十微秒，不代表整个键盘提速同等比例，也没有测量真机扩展延迟。没有为提速扩大永久缓存或增加词库。

## 未保留的静态索引实验

- 26×26键位距离表：46,358条签名一致，但冷查询累计耗时双拼2071→2130ms，全拼8532→8524ms，没有稳定收益。
- 二分查找改用 `memcmp`：签名一致，但同组累计耗时双拼2204ms、全拼9040ms，没有收益。

筛选计时不是隔离硬件基准，不据此断言这些技术普遍更慢；仅说明本轮证据不足以支持增加实现复杂度。两项均从生产撤回，`SKSpellingCorrector.swift`与基线保持一致。原始报告和实验源码保存在 `evidence/backend-round3/search/`，共用上轮冻结输入 `../backend-round2/search/inputs.json`。
