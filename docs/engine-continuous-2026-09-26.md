## 社区研究与取舍

检查了 Google Mozc 当前的 [lattice.cc](https://github.com/google/mozc/blob/master/src/converter/lattice.cc) 和 [immutable_converter.cc](https://github.com/google/mozc/blob/master/src/converter/immutable_converter.cc)。当前 `SetKey` 会清空 lattice，不能引用历史实现来声称现代 Mozc 直接复用这一层。本项目的缓存安全性来自本地代码的层次：静态词库转换没有用户历史，`SKJapaneseEngine` 每次重新应用学习排名。没有移植或声称实现 Mozc 的完整转换器。

也检查了扩大中文分词补充搜索的可能性。独立验收者冻结 6,737 个输入（高频词典编码和已有全拼样例），其中 3,629 个有多个音节切分。29 个输入第一次探测没有新结果，继续探测可给其中 24 个增加结果，但很多是“比啊哦准”“及呢嗯”“风跨嗯”“迪安娜哦”这样的机械拼接。相同音节数过滤仍不能证明质量提高。**不合入扩大探测/调整排序的改动**；24 个额外结果不是 24 个准确率提升。6,781 次真实 Rime 查询只作为发现证据，不作为成功质量指标。

## 性能和输出一致性

所有耗时是本机 macOS 的 Release 优化编译测试；不等同于 iPhone 键盘整体延迟。保留冻结输入与原始输出，性能数字不混用模拟查询和真实引擎。

### 中文分词

已有 840 组全拼样例加歧义、非法输入、长度边界，去重后逐前缀输入、删除和重输，共 34,080 个输出/查询路由签名。基线及 16/32/64 容量版本输出和查询次数一致。原生查询使用会随阶段改变返回值的 spy，刻意验证没有冻结真实候选。

| 范围 | 基线两次 P95 | 32 容量两次 P95 |
| --- | --- | --- |
| 冷分词 | 0.0644 / 0.0650 ms | 0.0690 / 0.0655 ms |
| 删除 | 0.0655 / 0.0656 ms | 0.00304 / 0.00296 ms |
| 重输 | 0.0647 / 0.0649 ms | 0.00296 / 0.00288 ms |

16 容量在较长编辑轨迹中频繁淘汰（重输 P95 约 0.0664 ms）；64 相比 32 没有足够新增收益，选 32。冷输入没有证明加速。这是分词 presenter 局部耗时，不包含真实 Rime 查询耗时。

### 日文转换

冻结已有 40 组日文样例，并另设 4 组重复 `nihon` 的长句压力输入。初次容量探索共 1,144 个签名一致；压力输入超过缓存容量会发生淘汰，**长句延迟尚未解决**。8 容量命中不充分，16 和 32 在正常编辑轨迹均能复用，因此选 16。

最终 UTF-8 键版本对 40 组正常样例反向顺序复测，共四轮、每轮 542 个完整候选签名，与基线完全一致：

| 范围 | 基线两轮 P95 | 最终版本两轮 P95 |
| --- | --- | --- |
| 冷转换 | 4.2928 / 4.1170 ms | 5.4087 / 4.1870 ms |
| 删除 | 3.9738 / 3.9571 ms | 0.001292 / 0.000875 ms |
| 重输 | 4.1333 / 4.2334 ms | 0.000292 / 0.000292 ms |

冷耗时有明显运行间波动，不主张冷转换改善；收益集中在命中已有转换的编辑轨迹。独立容量测试观测到 16 项合计 UTF-8 键和值载荷 1,326 字节，最多 21 个输出；这不是 RSS、Swift 容器开销或最坏内存上限。缓存具有条数及既有 80 字符输入界限，不宣称恒定 1,326 字节。

### 中日混

250 组真实引擎输入使用相同解码参数及空白用户目录。前十候选文本、目标词排名（在返回候选中查找）、意外上屏结果全部一致；双方 27 个行为检查全部通过。

- 基线按键 P95 12.1317 ms，优化后 9.3459 ms，下降约 23%。
- 累计按键耗时 28,458.0 → 21,589.9 ms，下降约 24%。
- 52 组 development 子集按“新、旧、旧、新”顺序复测：旧版 P95 14.1063 / 13.6309 ms，新版 12.3132 / 10.9803 ms；各轮前十候选、排名和上屏结果均一致。

这一项减少确定为零的评分工作，不改变搜索空间或分数；没有声称提高本轮准确率。先前误用 `MIXED_SPLIT=dev` 的零样例运行已排除，实际证据全部使用 `development` 或完整 250 组。
