# 简拼与未完成输入的候选

混合模式原先只接收「候选完整拼音是原始输入前缀」的 Rime 结果，又要求中文精确词图存在对应路径，因此 `w`、`wsm` 的有效候选被过滤。现在按音节匹配全拼、首字母和末音节前缀，以实际输入字母数记录消耗位置；选择 `wsmq` 中的「为什么」会保留 `q`。

全拼、双拼和混合模式会越过冗余长词，继续寻找单字；原先只读取前 128 个原生候选会漏掉 `wsm` 中排在第 745 位的「我」。当前按批读取，找到至少 128 个单字或扫描 4096 个候选后结束首轮；纯中文模式还可继续分页读取后面的单字。每组词语的六条配额按整次组合计算，翻页不会重新放入被截掉的长词。全拼和混合模式还会对合法的末音节前缀补充最多四个完整拼写查询，避免 `zhon` 被简拼路径挤掉「中」。选词时使用完整拼写提交，回车仍保留原始输入。自然码双拼沿用自身的 Rime 补全规则。

日文遇到未完成的罗马音时，从合法的罗马音规则生成读音前缀并查询词典；例如 `watash → 私`、`gakk → 学校`。单假名前缀查询当前音节，较长前缀也查询词语补全。混合模式的非精确中文候选和日文补全都需要词典依据；已有完整句子保留原有候选位置，补全使用剩余推荐位置和词语候选。混合模式只采用词典中的日文词语，假名兜底仅用于纯日文模式，以免未识别的中文尾巴被自动转成假名。原始字母仍用于显示、逐字删除和回车确认；选词学习记录完整读音。补全缓存只保存词典结果，最多 32 个输入，每个最多 64 项，用户学习在每次展示时重新排序。

运行 `bash scripts/test-prefix-candidates.sh`，使用随应用发布的真实词库检查全拼、双拼、日文和混合模式，覆盖首屏、展开候选、选词、空格、标点、删除、回车、简拼部分选择和日文补全学习。既有日文缓存测试同步改为检查未完成输入的候选会更新，不能残留上一轮已完成输入的候选。

上一轮前缀修复验证（分组调整前）：四模式 672/672 项；混合语料 250 组、62/62 项行为断言通过，250 组前六项候选与历史报告一致（按现行最多六条整句规则比较）。日文逐字删除 7661 项、缓存 28 项、Unicode 15 项和混合学习 16 项通过。iOS Release 无签名构建及打包词库一致性检查通过，未安装到实机。[结果与源码哈希](evidence/prefix-candidates/summary.json)。

## 候选分组（2026-09-27）

先保留最多六个优先推荐，再提供词典中的词语，按长词、三字词、两字词、单字排列。三字词与两字词各最多六项，已经进入优先推荐的同类词会占用该组配额，不会再次补出六项。四字及以上的词典词共用最多六个词语位置，防止长成语、日文长词被全部丢掉；混合、日文解码器可识别独立词条，因此这些词语和最多六个组合整句分别计数。纯 Rime 候选没有暴露“词/句”元数据，四字以上候选合计最多六项。单字不受六项限制。

`wsm` 在全拼和混合模式下为六个三字词、六个两字词，第十三项开始显示单字，例如「我、为、万、唯」。同组保留引擎原有排序和学习结果。选择「我」仅消耗 `w`，选择「我是」仅消耗 `ws`，剩余字母继续组成候选，回车保留尚未转换的尾巴。

日文按罗马字边界提供开头词语，例如 `watashihanihonjin` 可选「私」（消耗 `watashi`）后继续处理 `hanihonjin`；删除到确认边界可恢复原始拼写。假名原文仍在第三项，片假名原文仍可选择；这两个显式原文选项不占词句数量配额。
