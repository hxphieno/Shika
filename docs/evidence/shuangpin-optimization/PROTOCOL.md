## 分组隔离

先按以下关系建立目标的连通分组，再确定 split：相同目标、一个目标包含另一个完整目标、相同正确双拼码、预定义词族。额外绑定春夏秋冬、五种球类、付款/收款/退款、牙齿/牙刷、六种衣物词。长句包含的已选目标与该词同组。同音词两个目标必须同组。

每组的目标按 Unicode 排序，以 `|` 连接，计算 SHA-256 前 12 位得到 `family-<hash>`。对 `shika-sp-opt-v1|<family>` 再计算 SHA-256，前 8 位整数模 5 等于 0 为 development，否则 heldout，共 95 组。结果为 22 开发目标、118 保留目标。所有同一 target/family/correct 只属于一个 split。常见虚词和汉字共享不可避免；这里保证的是明确的目标及词族隔离，不声称字符级不重叠。

## 错键规则

使用 QWERTY 三行 `qwertyuiop`、`asdfghjkl`、`zxcvbnm`。某键的邻键取同行右侧，行尾取左侧。不查看错码是否合法，不筛掉误打后恰好成为另一合法双拼的样本，这类冲突必须纳入失败分析。

对于目标序号 i（0-based）、正确码 code、长度 n：

1. n < 16 时可错位置为 0…n−1；否则为 2…n−3。以目标文字 SHA-256 前 8 位整数对位置数取模确定 p。
2. substitution 将 p 的字母替换为邻键；omission 删除 p；insertion 在 p 前插入其邻键。
3. transposition 从所有相邻且不同的字母对中取第 i mod count 对；n ≥ 16 时仅用起点 2…n−4 的字母对，交换两字母。
4. double-error 在 `max(0, floor(n/3)−1)` 和 `min(n−1, floor(2n/3)+1)` 两个位置各替换为邻键。它代表两个替换，不冒充所有多错组合。

每项 edits 记录相对于正确码的 0-based 位置、旧片段和新片段。按位置逆序应用，必须逐字节重建 input。冻结检查已验证全部 840 条、全 ASCII 小写、clean 与 correct 相同、其他类不同。不会因为候选缺失而删除目标或更改 expected。

## 排名、完整消费与学习隔离

比较本轮改动前冻结的生产实现和最终实现，双方使用完全相同的语料、资源口径、优化编译、fresh user directory。另报原生无纠错基线可帮助解释来源，但不能代替与原版生产功能比较。

排名进程只输入和读候选，每项之前清空 composition；**不选词、不提交、不预先传入正确码/目标、不学习后重新算分**。排名过程中所有意外上屏必须为 0。开发/保留分别统计，全部分母保留。

Top1/5/10 和 MRR10 采用目标全文严格匹配，不能把前缀文本计为命中。只有能够消费完整输入并一次提交目标的路由可计入完整目标排名。原生候选可用其规范编码 comment 与完整 raw input 核对（忽略展示分隔，不忽略实质剩余编码）；负 index 的纠错候选必须有真实完整路由。证明不充分时记为“完整性未证实”，不能仅凭文本计为通过。

额外的每 case 独立提交验证使用独立进程与 fresh user data，选择当时显示的目标候选，要求输出恰好 target、无 input/preedit/candidates 残留、再次 commit 不重复。部分原生候选的行为在独立交互测试中验证，不算完整质量命中。提交测试不得训练排名进程。

同音组单独报告 target 覆盖；两个同音词不可能同时为首选，这不是实现缺陷。每种 kind、category、split、词长分别输出分母、命中、失败 ID。长句 exact-match 与原文完整保留分别报告，不能把“输出了某个句子”当作正确句子。

## 冻结门槛

- **行为硬门槛**：原文/候选上屏一次、Return、删除、部分选词、空格、标点、模式切换、分页路由、用户学习持久化、取消无学习全部通过；意外上屏与丢输入为 0。UI 和既有按键契约不变。
- **正确输入硬门槛**：heldout clean Top5 不下降；原版已命中目标首选的样本不得退为非首选。旧双拼/全拼质量与行为回归分别报告，不能仅用聚合平均掩盖退化。
- **双拼改善门槛**：heldout 四类单错（472 项）完整 Top5 相比旧生产版本至少提高 5 个百分点，即至少增加 24 个净命中；各类 118 项不得下降超过 2 个百分点（最多净减少 2 项）。未达标必须明确称为未达到本次预设收益门槛，不能改阈值后宣布通过。
- 双错、长句和同音组单独报告收益/失败，不能拿它们混入简单词制造漂亮总分。现阶段不给任意长句、多错设置虚构的绝对通过率。
- 同机稳态逐键 p95 不超过基线 1.25 倍且不超过 50 ms，p99 不超过 100 ms；异常负载导致超限时可说明环境并对两个版本同样复跑，不可只保留较快的一轮。冷启动、最大值、RSS 和复跑轮次一并保留。

## 独立测试修正记录

首轮行为原断言“nihcuijp 选你好 → 退格 → 输入 p → 空格应恢复你好世界”失败。对本轮冻结版本和改动前冻结版本运行同一测试，均为 68/69，唯一失败输出完全相同。原生 bridge 逐步诊断显示：第一次 Backspace 只撤销已确认的“你好”，input 仍为 `nihcuijp`；追加 p 得到 `nihcuijpp`，自然不是原句。这是测试错误假设，不是本轮删除回归。原生产逻辑没有改动。

修正后的断言为：第一次退格撤销部分确认、保留全部原码且不删除宿主文字；随后 Return 输出完整 `nihcuijp`。修正文件 SHA-256 为 `807b75bef9dba831044264150dcf66a73b71252067a2418e7e7e3c97166720f9`。首次报告、基线报告与原生逐步诊断保存在 `independent-dev1/`，不删除失败记录。
